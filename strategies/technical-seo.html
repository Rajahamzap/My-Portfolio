Helping search engines discover and understand important pages

#Crawlability, Indexation & Website Architecture

Technical SEO ensures that search engines can efficiently discover, crawl and understand the pages that matter.

#A. Robots.txt Optimization

  • Configure robots.txt to guide search engine crawlers toward the appropriate website sections.
  • Prevent unnecessary crawling of low-value or private areas where appropriate.
  • Ensure important content, CSS and JavaScript resources are not accidentally blocked.
  • Regularly review robots.txt rules to avoid unintended crawl restrictions.
Robots.txt controls crawling, not indexing

A robots.txt rule does not guarantee that a URL will be excluded from Google's index. A blocked URL can still appear in results if other pages link to it. To keep a page out of the index, use a noindex directive on a crawlable page or access controls.

#B. XML Sitemap Management

  • Create and maintain XML sitemaps containing canonical, indexable URLs.
  • Separate sitemaps by content type where appropriate.
  • Exclude redirected, duplicate and non-indexable URLs.
  • Submit sitemaps through Google Search Console.
  • Monitor sitemap processing and indexing status.
  • Update sitemaps as the website grows.

#C. Website Structure & Information Architecture

A logical content hierarchy helps users and search engines understand how pages relate to each other.

  • Organizing pages into relevant categories and subcategories.
  • Establishing clear relationships between pillar pages and supporting content.
  • Maintaining descriptive, SEO-friendly URL structures.
  • Keeping important pages accessible through logical navigation.
  • Avoiding unnecessarily deep page hierarchies.
  • Preventing duplicate and overlapping URL structures.
  • Designing scalable architecture that supports future content expansion.

#D. Internal Linking & Crawl Efficiency

Internal linking matters from both an SEO and a navigation perspective. For users, it shows where to go next. For search engines, it helps discover pages, understand topical relationships and distribute internal PageRank (link equity) across the website.

  • Linking relevant supporting articles to their pillar pages.
  • Connecting informational articles with relevant commercial pages.
  • Using descriptive and contextually relevant anchor text.
  • Identifying orphan pages and pages with insufficient internal links.
  • Prioritizing important pages within the website's internal linking structure.
  • Adding contextual links from high-authority internal pages to important target pages.
No fixed number of links per page

I do not prescribe a fixed number of internal links for every page. Links should be added where they provide genuine contextual value to the reader. The on-page side of this is covered in the On-Page SEO strategy.

#E. Canonical Tags, Redirects & Duplicate Content

  • Implement canonical tags to identify preferred versions of duplicate or similar URLs.
  • Use appropriate 301 redirects when URLs change permanently.
  • Resolve redirect chains and loops.
  • Identify duplicate and near-duplicate content.
  • Maintain consistent trailing slash and URL formatting rules.
  • Prevent unnecessary indexation of filter, parameter and duplicate URLs.

Performance, user experience and rendering

#Resource Optimization & Website Infrastructure

Website resources and infrastructure affect performance, user experience and how search engines render pages.

#A. Image Optimization

  • Compress images without noticeably reducing visual quality.
  • Use modern image formats such as WebP and AVIF where supported.
  • Serve images at appropriate dimensions rather than unnecessarily large originals.
  • Implement responsive images using srcset and sizes where appropriate.
  • Use descriptive filenames and meaningful alt text.
  • Avoid oversized images that increase page weight.

#B. Video Optimization

  • Compress and optimize video files.
  • Use appropriate video formats and dimensions.
  • Avoid unnecessarily large video files.
  • Consider external video hosting or streaming solutions when appropriate.
  • Prevent videos and embeds from creating unnecessary layout shifts.
  • Avoid loading heavy video resources before they are needed.

#C. Content Delivery Network (CDN)

A CDN distributes static resources through geographically distributed servers, so a visitor receives files from a location close to them rather than from a single origin server.

  • Serving images, CSS, JavaScript and other static resources from edge locations.
  • Reducing resource delivery latency.
  • Improving performance for geographically distributed visitors.
  • Using appropriate caching policies.
  • Optimizing image delivery through CDN capabilities where available.

#D. Hosting & Server Stability

  • Choose reliable hosting with sufficient server resources.
  • Monitor uptime and server response times.
  • Avoid unstable hosting environments.
  • Use server-side caching.
  • Optimize application and database performance.
  • Monitor resource usage as website traffic grows.

Structured data helps search engines understand the entities, relationships and information presented on a website.

#Implementation & Validation

  • Implement structured data using JSON-LD wherever appropriate.
  • Ensure schema properties accurately reflect visible page content.
  • Connect relevant entities through appropriate identifiers and relationships.
  • Avoid misleading, fabricated or irrelevant structured data.
  • Validate implementation using Google's Rich Results Test and the Schema Markup Validator.
  • Monitor structured data errors and warnings through Google Search Console.
Schema is not a guarantee

Schema markup improves machine readability and can help search engines interpret content. It does not guarantee rankings, rich results or AI citations.

Core Web Vitals measure real-world loading, responsiveness and visual stability.

Loading

Measures how quickly the main visible content loads.

Responsiveness

Loading performance

#Largest Contentful Paint (LCP) Optimization

How to identify and improve the loading performance of the largest visible element, often a hero image, a heading or other prominent content.

#A. Improve Server Response Time (TTFB)

#Use Fast Hosting

  • Choose hosting with reliable infrastructure and adequate resources.
  • Consider server location and visitor geography.
  • Monitor server response time under different traffic conditions.

#Enable Server Caching

Caching reduces repeated processing and speeds up resource delivery. These are the layers I consider:

Cache typeHow it helps
1. Full-page cacheStores the complete generated page so the server does not rebuild it for every visitor.
2. Object cacheKeeps the results of repeated database queries in memory.
3. Opcode cacheStores compiled script code so it does not need to be recompiled on every request.
4. Browser cacheLets returning visitors reuse files already downloaded.
5. CDN cacheServes cached static files from edge locations close to the visitor.

#Use a CDN

  • Cache static resources at edge locations.
  • Reduce geographic latency.
  • Optimize delivery of images, CSS and JavaScript.

#Optimize the Database

  • Remove unnecessary post revisions where appropriate.
  • Clean expired transients.
  • Optimize database tables.
  • Review inefficient database queries.
  • Remove unnecessary plugins and database overhead.

#B. Optimize Images — A Common LCP Bottleneck

  • Convert images to WebP or AVIF.
  • Serve appropriately sized images.
  • Implement responsive images.
  • Avoid unnecessarily large hero images.
  • Compress image files while maintaining acceptable quality.

#C. Preload the Hero Image

The main above-the-fold image should be discovered and requested early. If the browser only finds it late, for example inside CSS or after JavaScript runs, LCP is delayed.

  • Preload the actual LCP image when appropriate.
  • Ensure the correct responsive image is prioritized.
  • Avoid preloading multiple unnecessary images.

#D. Do Not Lazy-Load the LCP Image

The main image responsible for LCP should generally load eagerly rather than waiting for lazy-loading conditions. Lazy loading tells the browser to wait, which is the opposite of what the most important image needs.

#E. Prioritize Critical Resources

  • Using fetchpriority="high" for the actual LCP image where appropriate.
  • Prioritizing critical CSS and fonts.
  • Avoiding unnecessary resource preloads.
  • Ensuring critical resources are discovered early.

#F. Reduce Render-Blocking CSS

  • Remove unused CSS.
  • Minify CSS.
  • Inline critical CSS where appropriate.
  • Defer non-critical stylesheets when safe.
  • Reduce excessive CSS dependencies.
  • Review legacy CSS that is no longer required.

#G. Defer Non-Critical JavaScript

Unnecessary JavaScript can delay rendering and increase main-thread work.

  • Using defer for suitable scripts.
  • Using async where execution order is not required.
  • Deferring third-party scripts.
  • Removing unused JavaScript.
  • Avoiding unnecessary scripts in the initial loading path.

#H. Reduce JavaScript Execution

  • Break up long-running JavaScript tasks.
  • Reduce unnecessary DOM operations.
  • Avoid excessive event handlers.
  • Reduce heavy client-side rendering where possible.
  • Optimize third-party widgets and scripts.

#I. Optimize Fonts

  • Prefer modern WOFF2 font files.
  • Preload only critical fonts.
  • Reduce unnecessary font weights and variants.
  • Use font-display appropriately.
  • Ensure font loading does not unnecessarily delay visible content.

#J. Reduce Third-Party Scripts

I review unnecessary analytics, advertising, chat, tracking and marketing scripts. Non-essential scripts load only when needed, and third-party resources should not be allowed to block important page rendering.

#K. Avoid Heavy Sliders Above the Fold

Large carousels, sliders, animations and multiple image assets can increase loading time. I recommend simpler, lighter hero sections where possible.

#L. Optimize Background Images

  • Compress background images.
  • Use appropriately sized assets.
  • Prefer modern formats.
  • Preload important background images when necessary.
  • Avoid large background images that compete with the LCP resource.

#M. Above-the-Fold Loading Strategy

The key is the difference between critical and non-critical resources. Critical resources are needed to show the first screen. Everything else can wait.

  • Load essential above-the-fold content as early as possible.
  • Avoid lazy-loading the LCP image or other essential initial content.
  • Defer non-essential JavaScript and widgets.
  • Lazy-load below-the-fold images.
  • Delay heavy third-party embeds and non-essential AJAX requests until they are needed.
  • Avoid unnecessary scripts and requests during initial page rendering.
No indiscriminate lazy loading

Above-the-fold content must not be delayed by indiscriminate lazy loading.

Responsiveness

#Interaction to Next Paint (INP) Optimization

INP focuses on how quickly the page responds visually after a user interaction, such as clicking a button, opening a menu or submitting a form.

#A. Identify Long JavaScript Tasks

  • Identify long tasks that block the browser's main thread.
  • Use Chrome DevTools and performance profiling to locate expensive JavaScript execution.
  • Break up large tasks into smaller operations.
  • Avoid performing unnecessary calculations during user interactions.

#B. Optimize Event Handlers

  • Keep click, input and other event handlers lightweight.
  • Avoid excessive DOM manipulation.
  • Prevent unnecessary event listeners.
  • Debounce or throttle high-frequency events where appropriate.

#C. Defer Non-Critical JavaScript

  • Delay non-essential scripts.
  • Avoid loading unnecessary JavaScript during initial page interaction.
  • Reduce third-party script execution.
  • Load functionality only when required.

#D. Reduce Main-Thread Work

  • Minimize unnecessary JavaScript execution.
  • Avoid large synchronous operations.
  • Break up expensive tasks.
  • Use suitable browser scheduling techniques, including scheduler.yield() where supported and appropriate.

#E. Optimize Third-Party Widgets

I review chat widgets, analytics, advertising scripts, embedded tools and other third-party functionality that can interfere with interaction responsiveness.

#F. Reduce Unnecessary DOM Complexity

  • Avoid excessively large DOM structures.
  • Simplify complicated page components.
  • Minimize unnecessary rendering and layout calculations.
  • Optimize dynamic components and interactive elements.
The objective

The objective is to make user interactions respond quickly and predictably without blocking the main thread.

Visual stability

#Cumulative Layout Shift (CLS) Optimization

Unexpected movement of page elements creates a poor user experience. The fix is to reserve the space an element needs before it loads.

#A. Always Specify Image Dimensions

  • Add explicit width and height attributes to images.
  • Use appropriate aspect ratios.
  • Ensure image containers reserve space before image loading.

#B. Reserve Space for Ads and Embeds

Prevent layout shifts caused by

  • Google Ads.
  • YouTube embeds.
  • Google Maps.
  • Social media posts.
  • Third-party widgets.

Reserve appropriate dimensions for these elements before they load.

#C. Reserve Space for Dynamic Content

  • Define dimensions for dynamically loaded components.
  • Reserve space for banners, recommendations and notifications.
  • Prevent asynchronous content from pushing existing content down.

#D. Avoid Inserting Content Above Existing Content

  • Avoid unexpectedly inserting banners or elements above visible content.
  • Reserve space for announcements and promotional banners.
  • Use overlays or modals that do not disturb the document flow.
  • Use position: fixed for appropriate sticky notifications.

#E. Optimize Web Fonts

  • Use efficient font formats.
  • Preload critical fonts where appropriate.
  • Use suitable fallback fonts.
  • Match fallback font metrics to the primary font where possible.
  • Prevent font swaps from causing substantial text layout changes.

#F. Set Width and Height for Videos

Ensure video elements and embedded media reserve their required dimensions before loading.

#G. Use CSS Aspect Ratio

Use the CSS aspect-ratio property where appropriate for

  • Cards.
  • Product images.
  • Hero banners.
  • Thumbnails.
  • Videos.

#H. Avoid Animating Layout Properties

Avoid animations that repeatedly change layout-affecting properties such as width, height, top and left. Prefer transform and opacity animations when suitable.

#I. Keep Headers Consistent

Prevent unexpected header height changes during page loading, scrolling or interaction.

#J. Reserve Space for Lazy-Loaded Images

Ensure below-the-fold images have dimensions or aspect-ratio containers so they do not cause unexpected layout movement when loaded.

#K. Be Careful with Carousels and Sliders

  • Reserve fixed or predictable space for carousel containers.
  • Prevent slides with different dimensions from changing the layout.
  • Avoid unexpected height changes during transitions.

#L. Prevent Layout Shifts from Accordions

Use predictable layout behavior when expanding and collapsing accordion content. Avoid unexpected shifts caused by dynamically injected content or delayed resource loading.

Finding problems before they affect organic performance

#Technical SEO Auditing & Monitoring

Ongoing technical audits help identify problems before they affect organic search performance.

What I check

  • Weekly or scheduled website crawls using Screaming Frog.
  • Google Search Console monitoring.
  • Indexation and crawl error analysis.
  • Broken internal and external links.
  • Redirect chains and loops.
  • Canonical tag validation.
  • Missing metadata and heading issues.
  • Duplicate content identification.
  • XML sitemap validation.
  • Robots.txt testing.
  • Mobile usability and rendering checks.
  • Core Web Vitals monitoring.
  • Structured data validation.
